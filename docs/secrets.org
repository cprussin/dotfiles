* Secrets

Secrets are deployed out-of-band with colmena's ~deployment.keys~ mechanism
and never enter the nix store.

Modules declare keys with a ~keyCommand~ — an argv list executed on the
*deploying* machine at deploy time whose stdout becomes the key contents.  The
helpers in [[../lib/passwords.nix][lib/passwords.nix]] build ~keyCommand~s
that pull secrets from [[https://www.passwordstore.org/][pass]]; for example,
[[../modules/nixos/primary-user.nix][primary-user.nix]] sets the user's
hashed password from
~pass "Connor/Infrastructure/login/<user>@<host>"~.

On the target machine, keys are written to ~destDir~ (~/secrets~ in this
repo) and services reference them via ~config.deployment.keys.<name>.path~.

Keys are uploaded automatically as part of ~cli deploy~.  To upload keys
without a full deployment:

#+BEGIN_SRC bash
  cli upload-keys    # colmena upload-keys --on crux
#+END_SRC

Note that ~cli upload-keys~ targets crux by default, since crux holds the
service keys.

** Key uploads don't bounce services

Colmena uploads every key on every deploy, one at a time, and its
~<name>-key.service~ units bounce whenever their key file is replaced --
so anything that ~requires~ a key unit restarts once per key, changed or
not ([[https://github.com/nix-community/colmena/issues/174][colmena#174]],
[[https://github.com/nix-community/colmena/issues/177][colmena#177]]).
Deploys to crux run over wireguard, which depends on its key units, so each
upload used to knock down the tunnel the next one had to travel through.

[[../modules/nixos/batched-deployment-keys.nix][batched-deployment-keys.nix]]
makes key units wait for their key and then stay up across replacements, and
restarts the units whose keys actually changed once the deploy has gone quiet.
Consumers still depend on ~<name>-key.service~; they just restart at most once
per deploy, and only when a key really rotated.  Each key unit records the hash
of the key it came up with under ~/run/colmena-key-hashes~, and the reconciler
restarts the units whose key no longer matches -- so the record is per-boot by
design, and ~journalctl -u colmena-key-reconcile~ says what it restarted.
